## 1. Ringkasan & Daftar File

Task T6 mengimplementasikan integrasi Payment Gateway Bank Indonesia SNAP (NICEPay) secara menyeluruh pada service `billing` dan frontend Vue 3. Fitur mencakup:
1. Multi-bill checkout oleh orang tua dengan rincian fee transparan (BR-PAY-02, AC-27-01).
2. Verifikasi webhook SNAP berbasis tanda tangan asimetris RSA SHA-256 (AC-IF-01), audit keamanan terpusat, deduplikasi notifikasi idempoten `(provider_ref, raw_hash)` (AC-IF-02, BR-PAY-01), dan alokasi DB transaksi atomik (BR-FIN-03/04).
3. Penomoran kuitansi digital bebas celah (gapless) per sekolah dan tahun buku (`receipt_sequences`) yang aman konkuren (diuji 50 goroutines), cetak PDF, dan pengiriman notifikasi in-app/email (AC-29-01, AC-29-02).
4. Loket kasir pembayaran tunai/transfer langsung dengan pencetakan kuitansi instan (AC-29-03).
5. Pengajuan dan maker-checker koreksi pembayaran melalui Core Approval Center (AC-29-04).
6. Impor settlement batch CSV NICEPay, rekonsiliasi gateway vs settlement dengan penanganan exception (AC-31-01), dan rekonsiliasi rekening koran bank 50 baris dengan pencocokan toleransi tanggal dan nominal (AC-31-02).
7. Posting jurnal harian otomatis ke modul Accounting dengan antrean exception retry (AC-IF-03).
8. Dashboard analitik pembayaran sekolah (FR-26-001, AC-26-01).

## 2. Migrasi & Endpoint Baru

### Migrasi Database (`0003_gateway.up.sql` / `.down.sql`)
- `payment_methods`: Master metode (VA, QRIS, E-Wallet), skema fee (flat / basis poin), penanggung fee (`fee_bearer`), masa kedaluwarsa.
- `gateway_transactions`: Transaksi SNAP per sekolah, snapshot bills amount, fee, status, provider ref, VA / QR, masa berlaku.
- `gateway_transaction_bills`: Asosiasi multi-tagihan per transaksi dengan urutan alokasi.
- `gateway_notifications`: Log audit deduplikasi webhook SNAP `(provider_ref, raw_hash)`, status validasi signature.
- `receipts` & `receipt_sequences`: Kuitansi digital dengan nomor urut gapless per sekolah dan tahun buku (`receipt_sequences`).
- `cashier_payments`: Pencatatan transaksi loket kasir tunai / transfer langsung.
- `payment_corrections`: Pengajuan dan persetujuan koreksi transaksi (reassign / cancel).
- `settlement_batches` & `settlement_items`: Laporan batch settlement penyedia gateway.
- `reconciliation_exceptions`: Pencatatan selisih rekonsiliasi gateway vs settlement.
- `bank_statement_lines`: Baris mutasi rekening koran bank untuk auto-matching.
- `gateway_settings`: Pengaturan alokasi otomatis (earliest_due, component_priority, payer_choice) dan sub-akun.
- `gateway_accounts`: Pemetaan COA clearing, fee expense, piutang untuk posting jurnal.
- `student_deposits` & `deposit_movements`: Saldo kelebihan bayar siswa untuk alokasi otomatis di masa depan (BR-FIN-04).

## 5. Asumsi & Item Terbuka

1. **Sub-Account Parameter (FR-30-002, Should):**  
   Skema tabel `gateway_settings` telah memiliki kolom `sub_account_mode` dan `sub_account_id`. Pada spesifikasi SNAP donor `senb-v1`, parameter sub-account tidak disertakan secara baku dalam request payload standard SNAP (VA/QRIS). Dukungan pengiriman sub-account telah disiapkan dalam fungsi client request builder, namun integrasi endpoint sub-account resmi NICEPay perlu dikonfirmasi saat pengujian langsung dengan API Sandbox NICEPay Enterprise.
2. **Ketergantungan Eksternal (T1 Contract):**  
   Service `billing` telah mengimplementasikan panggilan HTTP ke modul `core` (`/internal/audit`, `/internal/approvals`, `/internal/exceptions`) dan modul `accounting` (`/api/internal/journals`) sesuai kontrak T1 menggunakan header `X-Internal-Key`. Pengujian unit dan integrasi handler menggunakan `httptest` server / mock internal.
3. **QRIS Rendering:**  
   Frontend menggunakan `qrcode` (SVG renderer) untuk menampilkan QRIS secara dinamis dari string `qr_content` tanpa ketergantungan pihak ketiga eksternal.
